# Local Adapter Contract

The application deliberately does not bundle vendor SDKs. A small normalized
provider bridge remains in the core; each selected service is supplied by an
outside connector/MCP or a private local helper. Installing one provider does not
increase the base application's dependency or startup cost.

## Contact discovery adapter

A compatible adapter must provide:

- A no-credit health/configuration check.
- Company and domain contact search.
- Optional email or phone unlock only when the request explicitly permits spending.
- Normalized contact output: name, title, company, email, phone, source, confidence,
  provider ID, and estimated credits used.
- Predictable errors for authentication, quota, rate limit, timeout, and no result.

The local helper is called with `--input <csv>`, `--output <csv>`,
`--max-contacts <number>`, and `--provider <provider-id>`. The
`--allow-paid-lookups` flag is present only after the operator approves a
credit-consuming request. A new helper must not spend credits when that flag is
absent.

## Mailbox adapter

A compatible adapter must provide:

- Account authorization and a no-send health check.
- Recent message ingestion with stable provider message/thread IDs.
- Draft creation separate from live sending.
- Live sending behind the backend lock and an exact user confirmation.
- Normalized sent, bounce, OOO, reply, and next-step events.

The generic mailbox helper command and response shapes are documented in
`docs/provider-adapters.md`. `OUTREACH_MAILBOX_HELPER` is provider-neutral.

## Writing and database adapters

Individualized in-app generation follows
[WRITING_ADAPTER_CONTRACT.md](./WRITING_ADAPTER_CONTRACT.md). Existing databases
follow [DATABASE_ADAPTER_CONTRACT.md](./DATABASE_ADAPTER_CONTRACT.md). Neither
adapter may accept credentials through browser configuration or workspace JSON.

## Reliability and privacy

- Use JSON at the adapter boundary and validate all input/output.
- Keep credentials in environment variables or the provider's credential store.
- Never return secrets in status responses or logs.
- Use bounded timeouts, retry only transient failures, and honor provider backoff.
- Make writes idempotent with provider IDs or an idempotency key.
- Isolate one provider/account failure so other configured paths can continue.
- Emit structured usage, timing, and error metadata for diagnostics.
- Block every provider call in public sample mode.

## LLM installation prompt

Use the provider-specific prompt generated by the setup screen. It includes the
selected role, official documentation, credential variable, and this contract.
The implementing AI should inspect existing adapters first, change only the provider
boundary, add fake-adapter tests, and verify that no secret is stored in browser
storage, logs, committed files, or test snapshots.
